10.4.0
======

Changed:
- SqlBulkOptions.EnableStreaming now defaults to false, matching
  SqlBulkCopy.EnableStreaming. Nothing fails to compile and no copy changes
  what it writes, so performance is the only place this shows. Turn it back
  on for rows carrying a varchar(max), nvarchar(max) or varbinary(max) column
  whose values are large enough that SQL Server stores them off-row, which is
  the case the flag exists for:
  WriteDataAsync(records, options => options.EnableStreaming = true). Where
  every value fits in-row the previous default had nothing to stream and
  still paid for the machinery, an allocation per column on every row.
- The two remaining defaults are now documented rather than merely stated.
  BulkCopyTimeout stays at 0, deliberately unlike SqlBulkCopy's thirty
  seconds, because a copy of millions of rows outlives that limit and would
  be abandoned part-written. CopyOptions stays at SqlBulkCopyOptions.Default,
  which is what an unconfigured SqlBulkCopy uses.

----------------------------------------------------------------------

10.3.0
======

Added:
- WriteDataAsync now accepts an IAsyncEnumerable<TEntity> alongside
  IEnumerable<TEntity>. The sequence is enumerated once and lazily, so rows
  produced asynchronously (by another database, an HTTP API or a queue) stream
  straight into SqlBulkCopy instead of being collected into a list first. The
  cancellation token is passed to GetAsyncEnumerator, so a producer written as
  an asynchronous iterator observes it as well as the copy does.

Changed:
- WriteDataAsync no longer compiles when the compiler cannot tell which of the
  two overloads is meant: an untyped null literal, and any argument whose
  static type implements both IEnumerable<TEntity> and IAsyncEnumerable<TEntity>
  (Entity Framework Core's DbSet<TEntity>, for example). Neither interface
  converts to the other, so neither overload wins. Cast the argument to the one
  you want, for example WriteDataAsync((IEnumerable<Record>)source), which also
  states at the call site whether the source is read synchronously or
  asynchronously.

10.2.2
======

Changed:
- Packages are now published to NuGet.org through trusted publishing, so the
  release pipeline no longer depends on a long-lived API key.

10.2.1
======

Fixed:
- Bulk-write operations no longer capture the caller's synchronization context,
  preventing a potential deadlock when the returned task is awaited or blocked on
  from a single-threaded or UI context.

----------------------------------------------------------------------

10.2.0
======

Added:
- Documented the destination table name contract: the name is passed to
  SqlBulkCopy verbatim, so the caller owns quoting and multi-part qualification
  (for example [schema].[table]).

Changed:
- WriteDataAsync now fails fast with InvalidOperationException when no property
  has been mapped, and opens the connection whenever it is not already open
  (previously only a Closed connection was opened, leaving Broken/Connecting to
  fail later).
- Faster per-cell bulk-copy reads: the data reader now uses an array-backed
  accessor store with a constant-time indexer.

Fixed:
- The data reader now honors the IDataReader contract: GetBytes and GetChars
  return the field length when given a null buffer, GetOrdinal throws
  IndexOutOfRangeException for an unknown column name, accessing a field before
  the first read throws InvalidOperationException, HasRows reports false for an
  empty source, and GetSchemaTable returns an independent copy whose column
  names match GetName.

----------------------------------------------------------------------

10.1.0
======

Fixed:
- Column name quoting now escapes embedded closing brackets, so a column name
  that contains ']' is quoted correctly.

Changed:
- CreateBulkContext now validates its arguments: it throws ArgumentNullException
  for a null connection and ArgumentException for a null or whitespace table
  name. WriteDataAsync throws ArgumentNullException when the entity collection is
  null.
